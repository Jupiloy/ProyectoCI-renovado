# Matriz de integración: frontend Figma y backend Django

Fecha de inspección estática: 27/10/2026. Frontend inspeccionado: `TesisMCP/` (el prototipo visual recuperado), no `TesisMCP_Frontend/`. Backend inspeccionado: `backend/config/urls.py`, `backend/config/auth_views.py`, `backend/config/api.py`, `backend/thesis/api/routes_*.py`, sus esquemas y los servicios citados abajo. Esta matriz combina inspección de código, comprobaciones focalizadas de 1A/1B y el corte 2C por HTTP con Vite, Django y PostgreSQL aislado; **no acredita interacción visual en navegador**. `TesisMCP/src/App.tsx` ya consume los módulos de sesión y proyectos, que usan `TesisMCP/src/api/client.ts`. Las pantallas anteriores de ejemplo permanecen en `DemoApp.tsx`.

## Reglas transversales verificadas

- Django publica sesión en `/api/v1/auth/session/`, `/api/v1/auth/login/` y `/api/v1/auth/logout/`; Ninja publica proyectos bajo `/api/v1/projects` e integraciones bajo `/api/v1/integrations`. Las rutas de sesión terminan en `/`; las de Ninja se muestran tal como están declaradas.
- `GET /auth/session/` devuelve `authenticated`, `user` y `csrf_token`. El login requiere JSON `{email,password}`, cookie de sesión y CSRF. El acceso real consulta sesión y usa correo, contraseña y CSRF; el selector de rol solo existe en `DemoApp.tsx`. El rol real procede de la membresía de cada proyecto.
- `TesisMCP/src/api/client.ts` aporta transporte con prefijo `/api/v1`, `credentials: include`, CSRF en cabecera y errores que conservan el estado HTTP; `auth.ts` y `projects.ts` implementan los endpoints de 1B. Se identifican respuestas conocidas de CSRF y denegación de permiso; las respuestas binarias todavía requieren tratamiento propio. Los campos `expected_version` e `idempotency_key` de varios PUT/POST van en el **JSON** del backend; la cabecera `If-Match` del cliente no los sustituye. Las subidas usan `FormData`, así que no deben forzar `Content-Type: application/json`.
- `App.tsx` gestiona sesión real, selección autorizada y espacio inicial del proyecto; las cinco vistas ficticias y la hoja `contentEditable` permanecen aisladas en `DemoApp.tsx`. `index.css` conserva el diseño; el modo real admite anchos desde 360 px y la demo mantiene un ancho mínimo de 900 px. Las siguientes integraciones deben usar datos reales o estados vacíos.
- El piloto se detiene antes de elaborar/aplicar instrumentos. P26/P27 requieren decisión metodológica; el catálogo de 32 pasos no equivale al recorrido fijo de cada proyecto. IEEE es prioritario en el piloto; APA 7 permanece por compatibilidad. En el modal actual de citas aparecen APA y Vancouver, lo cual no representa esa prioridad.

## Orden de implementación y modelo recomendado

1. **Acceso y selección de proyecto**: Sol High para contrato/permisos y posible `GET /projects`; Luna para formularios y navegación una vez fijado el contrato.
2. **Documento versionado**: Sol High para editor↔árbol v2, guardado, CSRF/conflictos y citas; Luna para extraer componentes visuales sin alterar lógica ni estilos.
3. **Recorrido configurable y pasos**: Sol Medium para contrato/dependencias; Luna para interfaz delimitada.
4. **Biblioteca y pasajes**: Luna para vistas/carga; Sol High para procedencia, estados y errores.
5. **Asesor, snapshots e invitaciones**: Sol High para permisos/anclajes/decisiones; Luna para presentación.
6. **Agente BYOA**: Sol High para contrato y conector. Astra solo si surge bloqueo arquitectónico comprobado.
7. **Citas asistidas, tablas/figuras y exportación**: Sol High para integridad documental; Luna para componentes con contrato cerrado.
8. **Recorrido integrado y verificación final**: Sol High. No usar textos o cifras de la demostración como evidencia de funcionamiento.

## Criterio de cierre de este inventario

El corte 2C comprobó el contrato HTTP de sesión, proyecto y documento con datos sintéticos aislados; la interacción visual en navegador y la puerta integral siguen pendientes. Antes de implementar cada fila: confirmar esquema, permisos y comportamiento en el código vigente. El usuario pidió reservar la puerta integral para el cierre de las correcciones.
